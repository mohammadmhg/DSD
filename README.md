# پروژه شتاب‌دهنده سخت‌افزاری شبکه عصبی (VHDL)

این پروژه در ۴ فاز پیاده‌سازی می‌شود:

1. **فاز ۱ – آموزش نرم‌افزاری (Python)** ✅ آماده است.
2. **فاز ۲ – کوانتیزاسیون و تبدیل به ممیز ثابت (Fixed-Point)** ✅ آماده است.
3. **فاز ۳ – طراحی سخت‌افزار در VHDL** ✅ آماده است.
4. **فاز ۴ – شبیه‌سازی و اعتبارسنجی (Testbench)** ✅ آماده است.

## معماری شبکه (فاز ۱)

برای اینکه پیاده‌سازی سخت‌افزاری در فازهای بعدی معقول و قابل‌مدیریت باشد،
تصاویر MNIST (که اصالتاً ۲۸×۲۸ پیکسل هستند) به ۸×۸ پیکسل (۶۴ ورودی) کاهش
بعد داده می‌شوند. این دقیقاً همان «کاهش بعد تصاویر» است که در ساختار گزارش
نهایی پروژه هم خواسته شده.

```
ورودی (64) -> لایه پنهان (16 نورون، ReLU) -> لایه خروجی (10 نورون = ارقام 0 تا 9)
```

## نحوه اجرا

```bash
# ساخت و فعال‌سازی محیط مجازی (از ریشه پروژه)
python3 -m venv venv
source venv/bin/activate        # ویندوز: venv\Scripts\activate

# نصب پیش‌نیازها
pip install -r requirements.txt

# رفتن به پوشه فاز ۱ و اجرای مراحل به ترتیب
cd phase1_software_training
python train.py                 # آموزش مدل (دیتاست MNIST به‌صورت خودکار دانلود می‌شود)
python export_params.py         # استخراج وزن‌ها و بایاس‌ها
python export_test_samples.py   # استخراج چند نمونه تست برای فاز ۴ (Testbench)
```

## خروجی‌های فاز ۱ (پیش‌نیاز فازهای بعدی)

- `outputs/model_checkpoint.pth` — وزن‌های آموزش‌دیده مدل (فرمت PyTorch)
- `outputs/params/*.txt` — وزن‌ها و بایاس‌ها به‌صورت متنی (ورودی فاز ۲)
- `outputs/test_samples/*.txt` — نمونه تصاویر تست + برچسب واقعی + خروجی مدل پایتون (ورودی فاز ۴)

## فاز ۲ — کوانتیزاسیون (Fixed-Point)

پوشه: `phase2_quantization/`

```bash
cd phase2_quantization
python quantize_and_evaluate.py   # کوانتیزه‌سازی + مقایسه دقت + خروجی برای فاز 3 و 4
python bitwidth_sweep.py          # (اختیاری، برای گزارش) مقایسه چند فرمت Q(m,n) مختلف
```

- فرمت پیش‌فرض: **Q(8, 8)** — ۸ بیت صحیح (شامل علامت) + ۸ بیت اعشاری = ۱۶ بیت. برای تغییرش کافیه مقادیر `QM` و `QN` بالای `quantize_and_evaluate.py` رو عوض کنی.
- `fixed_point_utils.py` علاوه بر تبدیل float↔fixed، تابع `fixed_point_layer` رو هم داره که یک لایه‌ی کامل (ضرب‌ها + جمع انباشته با accumulator عریض + rescale با شیفت + saturation + ReLU) رو **دقیقاً مثل سخت‌افزار** با عدد صحیح شبیه‌سازی می‌کنه. به همین خاطر دقتی که این اسکریپت گزارش می‌ده، همون دقتیه که سخت‌افزار فاز ۳ باید بهش برسه.

### خروجی‌های فاز ۲ (پیش‌نیاز فازهای بعدی)

- `outputs/params_fixed/*_dec.txt` و `*_hex.txt` — وزن‌ها/بایاس‌های کوانتیزه‌شده (دسیمال و هگز) → برای مقداردهی اولیه ROM در فاز ۳
- `outputs/test_samples_fixed/*.txt` — تصاویر تست کوانتیزه‌شده + پیش‌بینی سخت‌افزاری شبیه‌سازی‌شده → مرجع مقایسه برای Testbench فاز ۴

## فاز ۳ — طراحی سخت‌افزار (VHDL)

پوشه: `phase3_vhdl_hardware/`

```
phase3_vhdl_hardware/
├── rtl/
│   ├── nn_pkg.vhd            # ثابت‌ها، انواع آرایه‌ای، توابع saturate/rescale/relu
│   ├── mac_unit.vhd          # واحد ضرب-جمع انباشته (MAC)
│   ├── relu_unit.vhd         # بلوک مستقل ReLU (برای نمودار بلوکی گزارش)
│   ├── neural_network.vhd    # ماژول اصلی: FSM کنترل + مسیر داده
│   └── roms/                 # (با اسکریپت زیر ساخته می‌شود؛ داخل ریپو نیست)
├── scripts/
│   └── generate_vhdl_roms.py # خروجی فاز ۲ را به ۴ فایل ROM سنتزپذیر VHDL تبدیل می‌کند
└── sim/                       # تست‌بنچ کامل اینجا در فاز ۴ ساخته می‌شود
```

### مرحله ۱: ساخت ROM وزن‌ها از خروجی فاز ۲

**این مرحله را حتماً بعد از اجرای فاز ۲ با داده‌ی واقعی MNIST انجام بده** (نه با داده‌ی آزمایشی):

```bash
cd phase3_vhdl_hardware/scripts
python generate_vhdl_roms.py
```

این اسکریپت فایل‌های `phase2_quantization/outputs/params_fixed/*_dec.txt` را می‌خواند و ۴ فایل
`weights_hidden_rom.vhd`، `bias_hidden_rom.vhd`، `weights_output_rom.vhd`، `bias_output_rom.vhd`
را داخل `rtl/roms/` می‌سازد (هرکدام یک آرایه‌ی ثابت VHDL که به‌صورت ترکیبیِ آدرس‌پذیر خوانده می‌شود).

### مرحله ۲: کامپایل (Analyze) با GHDL

اگر [GHDL](https://ghdl.github.io/ghdl/) نصب داری (متن‌باز و رایگان، جایگزین خوبی برای
ModelSim برای بررسی سریع سینتکس/معنایی):

```bash
cd phase3_vhdl_hardware
mkdir -p work && cd work

ghdl -a --std=08 --work=work ../rtl/nn_pkg.vhd
ghdl -a --std=08 --work=work ../rtl/mac_unit.vhd
ghdl -a --std=08 --work=work ../rtl/relu_unit.vhd
ghdl -a --std=08 --work=work ../rtl/roms/weights_hidden_rom.vhd
ghdl -a --std=08 --work=work ../rtl/roms/bias_hidden_rom.vhd
ghdl -a --std=08 --work=work ../rtl/roms/weights_output_rom.vhd
ghdl -a --std=08 --work=work ../rtl/roms/bias_output_rom.vhd
ghdl -a --std=08 --work=work ../rtl/neural_network.vhd
```

اگر همه‌ی دستورها بدون خطا تمام شدند، یعنی کدها از نظر سینتکسی و نوع‌داده‌ای درست‌اند و آماده‌ی
شبیه‌سازی با تست‌بنچ فاز ۴ هستند. برای **ModelSim** یا **Vivado** هم همین فایل‌ها را دقیقاً به همین
ترتیب (چون به هم وابسته‌اند) به پروژه اضافه کن.

### نکته‌ی مهم درباره‌ی صحت طراحی (تأیید شده)

این طراحی با GHDL کامپایل و با یک تست‌بنچ موقت شبیه‌سازی شد: ۱۰ تصویر تستِ کوانتیزه‌شده از فاز ۲
به ورودی `neural_network` تزریق شدند و رقم پیش‌بینی‌شده‌ی سخت‌افزار (شبیه‌سازی‌شده) با پیش‌بینیِ
مدل فیکسد-پوینتِ پایتون (`fixed_point_utils.py`) مقایسه شد — **هر ۱۰ مورد دقیقاً یکسان بودند**.
یعنی معماری MAC + Rescale/Saturate + ReLU + FSM دقیقاً همان محاسباتی را انجام می‌دهد که در فاز ۲
با پایتون شبیه‌سازی کردیم؛ الان می‌تونی با خیال راحت روی این پایه فاز ۴ (تست‌بنچ کامل + تحلیل
زمان‌بندی و منابع) رو بسازی.

### معماری و کارایی

طراحی از **یک واحد MAC مشترک** استفاده می‌کند که به‌ترتیب برای همه‌ی نورون‌ها استفاده مجدد
می‌شود (یک ضرب-جمع در هر سیکل کلاک) — این انتخاب مصرف منابع سخت‌افزاری (LUT) را کم نگه می‌دارد،
با هزینه‌ی تأخیر بیشتر. برای هر طبقه‌بندی: تقریباً `(64+3)×16 + (16+3)×10 + چند سیکل اضافه` سیکل
کلاک لازم است. اگر بخواهی سریع‌تر باشد (با مصرف منابع بیشتر)، می‌توان ۱۶ واحد MAC موازی برای لایه‌ی
پنهان استفاده کرد — این trade-off را می‌توانی در گزارش نهایی بحث کنی.

### اجرا

بعد از این‌که فازهای ۱ تا ۳ را با داده‌ی واقعی MNIST انجام دادی (و ROMهای فاز ۳ را ساختی):

```bash
cd phase4_simulation/scripts
bash run_simulation.sh
```

این اسکریپت:
1. تمام فایل‌های VHDL فاز ۳ + تست‌بنچ را با GHDL کامپایل می‌کند.
2. شبیه‌سازی را اجرا می‌کند: هر ۱۰ نمونه‌ی تست فاز ۲ را می‌خواند، به ورودی `neural_network`
   تزریق می‌کند، و برای هر نمونه گزارش می‌دهد:
   - `hw_predicted` (خروجی سخت‌افزار) در مقابل `true_label` (برچسب واقعی) → دقت واقعی
   - `hw_predicted` در مقابل `python_predicted` (خروجی مدل فیکسد-پوینت پایتون فاز ۲) →
     **باید ۱۰۰٪ یکسان باشد**؛ این تأیید می‌کند سخت‌افزار دقیقاً همان محاسبه‌ی نرم‌افزار را انجام می‌دهد.
   - `latency` (تعداد سیکل کلاک از شروع تا پایان طبقه‌بندی)
3. یک خلاصه‌ی آماری در پایان چاپ می‌کند (دقت کلی، حداقل/میانگین/حداکثر تأخیر، تأخیر بر حسب
   نانوثانیه با فرض کلاک ۱۰۰ مگاهرتز).
4. یک فایل موج (`waveforms/tb_neural_network.vcd`) می‌سازد که با
   [GTKWave](https://gtkwave.sourceforge.net/) (رایگان و متن‌باز) می‌تونی بازش کنی و تصویرشو
   برای بخش «نتایج شبیه‌سازی» گزارش بگیری:
   ```bash
   gtkwave waveforms/tb_neural_network.vcd
   ```
